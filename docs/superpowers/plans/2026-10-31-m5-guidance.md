# M5: Guidance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app tells the farm what to do. Each pond's page becomes a dashboard (F6), with:
- ration and feedings for today;
- days since the last weighing;
- period FCR with a trend arrow;
- survival;
- the latest water reading;
- open alerts;
- three charts.

An Alerts tab lists every open alert and due task, danger first, filterable by pond. Tapping one opens the screen that fixes it (F7). The worker's pond tiles show today's ration and a "don't feed" sign when the fish must not be fed.

**Architecture:**
- **No schema change.** Alerts, FCR and survival are derived values, never stored (SPEC §4).
- **One load of facts.** A new pure `FarmFacts` holds every current stocking, transfer, sample and daily log. It is loaded once per table change, and placements, growth and alerts are all computed from it.
- **Pure domain logic.** New domain files hold it all:
  - `farm_facts.dart`
  - `growth.dart`, for weighing points, FCR periods, survival and daily deaths
  - `alerts/farm_alerts.dart`, which applies every rule from DOMAIN §Alert rules to the facts
  - `alerts/worker_advice.dart`, for stop-feeding advice
- **Thin screens.** Features map Drift rows to small domain inputs and draw the results.
- **Charts.** `fl_chart` draws them, behind one small `MiniChart` wrapper.

**Tech Stack:** Flutter 3.47.8, Drift 2.35, flutter_riverpod 3 (no codegen), go_router 18, ARB l10n (fr; mg for worker strings). New dependency: `fl_chart` (latest stable).

**Spec:** `CLAUDE.md`; `docs/SPEC.md` (F6, F7, §6 navigation, §7 sync "Duplicates across phones", §11 M5); `docs/DOMAIN.md` (§Feeding, §Sampling, §Formulas, §Water quality, §Alert rules). The decisions below are Claude's calls, made without the user. They can be revisited.

## Decisions (Claude's calls)

1. **Rules whose data isn't recorded yet stay off.** Feed stock low, feed too old and pond prep step need feed lots and prep steps, which arrive in M7 (F10, F11). Their domain functions already exist, and `farmAlerts` gets those inputs in M7. Pre-harvest fast does work now, because the batch form has had a planned harvest date since M2.
2. **Harvest time.** A planned harvest is taken to start at 06:00 Madagascar time on its date (DOMAIN [8.2], "early morning"). The 48 h fasting window ends then. This adds a new config value, `harvestHour = 6` **[default]**.
3. **Mortality spike stays open for 3 days.** Each of the last `mortalityLookbackDays = 3` **[default]** days is checked, and the most recent day that spiked is reported with its date. Without this window, a member visiting weekly would never see a spike.
4. **Stop-feeding advice for the worker** (DOMAIN §Feeding [5.3], SPEC F7). A pond's tile shows a crossed-out bowl when any of these holds:
   - the pre-harvest fast is on;
   - the latest reading has oxygen below the minimum;
   - surface swimming or erratic swimming was logged today or yesterday (`stopFeedingSignDays = 2` **[default]**).

   This is the worker's whole task list, together with the ration shown on each tile. Workers never see the Alerts tab.
5. **Weighing points.** A batch's growth in a pond is a list of weighing points:
   - its arrival in the pond (first stocking or move in), with that record's average weight;
   - then each sample.

   The live count at a point is the count at the end of that farm day. Because arrival counts as a point, the first sample already gives an FCR.
6. **Period FCR** for one batch in one pond, between two consecutive weighing points:
   - **Feed:** the pond's daily-log feed dated after the earlier point, up to and including the later one.
   - **Moves:** moves out of or into the pond in the same window count at their own average weight, or, if they weren't weighed, at the earlier point's weight.
   - **Shared ponds:** if another batch had fish in the pond during the period, the FCR is "not computable" (`null`), shown as "—". Pond feed can't be split between batches honestly.
7. **FCR trend:** the latest computable period compared with the one before. `worse` if higher, `better` if lower, `same` if equal to 2 decimals. Shown as ↑ (red), ↓ (green) or →.
8. **Survival** is per batch over all its ponds: live fish ÷ fish stocked (moves between ponds neither add nor remove). It's shown on each batch card of the pond page.
9. **Water out of range** applies to ponds holding fish. It uses the latest reading's temperature, pH and oxygen. For colour, it uses whichever is more recent: the reading's colour or the latest daily log's colour.
10. **Warning signs** come from daily logs (warning signs and signs on dead fish) and health events, in the last 3 days or dated in the future.
11. **Duplicate pond-days** (SPEC §7) show up as a warning alert, `duplicateDailyLog`, listing the current logs. Tapping it opens a screen that shows them side by side with "Garder celui-ci" (keep this one) on each. Keeping one writes a tombstone for each of the others. Two current corrections of the same sample or reading (rarer) aren't flagged in M5.
12. **Order:** danger first; then by kind, in DOMAIN table order with `duplicateDailyLog` last; then by pond code. The pond filter is a row of chips, one per pond that has alerts, plus "Tous" (all).
13. **Where tapping leads:**

    | Alert | Opens |
    |---|---|
    | water out of range, water check due | `/water/:pondId` |
    | sample due | `/sample/:pondId?batchId=` |
    | mortality spike, warning sign seen | `/ponds/:pondId/problem` |
    | quarantine ending | `/transfer?batchId=&fromPondId=` |
    | duplicate daily log | `/ponds/:pondId/duplicates?date=yyyy-mm-dd` |
    | FCR worsening, growth stalled, density, phase change, pre-harvest fast | `/ponds/:pondId` |
14. **Navigation:**
    - **Alerts tab.** It sits between Visit and More (SPEC §6; Reports joins in M6). Its icon carries a red badge with the count of danger alerts.
    - **Pond cards.** On the Ponds list, each card adds today's ration plus a danger count and a warning count.
15. **Charts:**
    - average weight per weighing point, one line per batch in the pond;
    - deaths per day over the last 30 days, as bars;
    - FCR per period, as points, with stalled periods drawn as a red mark on the axis.

    They're drawn with `fl_chart` (the user's choice: the APK should stay moderate in size, not minimal), behind one `MiniChart` wrapper. The wrapper holds the shared look, the empty state, the semantics label, and animations turned off (`duration: Duration.zero`) for low-end phones. The 30-day window is a display choice, kept in the widget file rather than in config.
16. **Placements.** `placementsProvider` now derives from `farmFactsProvider`, so the facts load once per change. `BatchRepository.watchPlacements` and `currentPlacements` stay, rebuilt on `currentFacts`.
17. **Language.** Member screens stay French. The new worker strings (ration on the tile, the three stop-feeding reasons as icon labels) get Malagasy, marked for review in M8.

## Global Constraints

- Offline only; nothing in M5 touches the network or the server schema. No Drift schema change, so `schemaVersion` stays 4.
- `lib/domain/` imports neither Flutter nor Drift (`test/domain/purity_test.dart`). Every farming number comes from `DomainConfig`, and each new one gets a DOMAIN.md line, an override key in `config_overrides.dart`, a settings label and an ARB entry.
- Weights are integer grams; average weights are doubles in g. Dates are farm dates via `daysBetween`, `farmDate` and `farmDateToUtc`; ordering uses the recorded date, never the device clock.
- Estimated values (live count, biomass, ration) are shown with `EstimatedLabel`.
- Every string comes from the ARB files. Touch targets are ≥ 56 dp. Every pushed screen has a working Back. Every Save or Keep goes through `SaveOnce`.
- At the end of each task: `flutter analyze` has no issues, and `flutter test` and `TZ=UTC flutter test` pass.
- Commits use a conventional prefix and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Branch: `feat/m5-guidance` from `main`.

## Review Focus

1. **A pond holding two batches:** the FCR shows "—", never a number made from the whole pond's feed. The ration still adds both batches. Test in Task 2.
2. **A typo of 500 deaths in a pond of 300 fish:**
   - mortality spike fires;
   - live count is 0, flagged inconsistent;
   - survival is 0 %, never negative;
   - FCR is "stalled", with no division by zero or crash.

   Tests in Task 2 and Task 3.
3. **A phone whose clock is days ahead:** a warning sign dated in the future still raises an alert, and "days since last weighing" for a sample dated in the future shows 0, never a negative number. Tests in Task 3 and Task 9.
4. **Running under `TZ=UTC` at 23:30 Madagascar time (20:30 UTC):** the day's log counts for that farm day in mortality spike and stop-feeding advice, and "sample due" counts farm days. Test in Task 3.
5. **Resolving a duplicate pond-day that another phone already resolved:** the second "Garder" shows the stale-record message and writes nothing. Test in Task 7.
